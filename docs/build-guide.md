# Build Guide

There are two kinds of build:

- **Applications** (a bitstream and a C program). Needs Vivado and the SDK.
  This is all you need if you use a release image; see `adding-an-app.md`.
- **The Linux image** (kernel, rootfs, boot files, SDK). Needs PetaLinux. Only
  needed to produce a release or to change the image itself.

`make help` lists every target and the discovered applications.

## Prerequisites

- Vivado 2024.1, with ZCU102 board files installed (provides `bootgen`)
- For C applications: the SCAM SDK, from a release or from `make sdk`
- For the Linux image: PetaLinux 2024.1, and either an AMD-supported Linux
  host or Docker for the Ubuntu 22.04 container
- For SD flashing: `parted`, `mkfs.vfat`, `mkfs.ext4`, `tar`

`make doctor` checks all of this on your machine and says how to fix what is
missing (`make doctor FULL=1` also proves a Vivado license can be checked out).
`make status` shows what has been built and what is out of date.

Vivado always runs on the host. The container handles PetaLinux only; it
consumes the XSA generated by Vivado.

## Machine settings: `config.mk`

Copy `config.mk.example` to `config.mk` (gitignored) and set what your machine
needs. Everything can also be given on the `make` command line.

| Variable | Meaning | Default |
| :-- | :-- | :-- |
| `PETALINUX_ENV` | `host` or `container` | `host` |
| `PETALINUX_ROOT` | PetaLinux 2024.1 installation | `~/petalinux/2024.1` |
| `VIVADO_SETTINGS` | Vivado `settings64.sh` to source | unset: `vivado` from `~/.bashrc` function or `PATH` |
| `SCAM_JOBS` | parallel Vivado implementation jobs | `8` |
| `SCAM_APPS` | application directories outside the repository | none |
| `SCAM_SDK` | installed SDK used by `make app-<name>` | none |

## Applications

    make base-xsa            # hw/base/system.xsa (and the template project)
    make bitstreams          # every application: build/apps/<app>/<name>.bit.bin
    make <app>-bitstream     # one application
    make apps                # every binary: build/apps/<app>/yeet-data-<app>
    make app-<app>           # one binary
    make deploy APP=<app> TARGET=<user@board>

Bitstream targets depend on the base XSA and on the files in the application's
`hw/` directory, so an unchanged bitstream is not rebuilt. Each application
gets its own Vivado project and log under `build/apps/<app>/`.

Every bitstream build ends with the PL contract check described in
`pl-contract.md`.

## The Linux image

    make petalinux           # configures first if needed, then builds
    make sdcard              # BOOT.BIN + petalinux-sdimage.wic, assemble ./out/
    make flash SD=/dev/sdX   # partition the card and write ./out/ to it
    make sdk                 # images/linux/sdk.sh
    make release             # out/release/: .wic.xz, boot tarball, SDK, checksums

Or, for everything up to the SD card files:

    make all

`make petalinux` builds the bitstreams the image installs first, and runs
`petalinux-config` when the base XSA is newer than the last configuration.
`make petalinux-config` forces a configuration run.

`make sdcard` runs `petalinux-package boot`, which creates `BOOT.BIN` from the
FSBL, PMU firmware, TF-A and U-Boot. No bitstream is put into `BOOT.BIN`; the
PL is loaded after boot by `fpga-load.service`.

### Using the container

    make petalinux PETALINUX_ENV=container

or set `PETALINUX_ENV := container` in `config.mk`.

Each user supplies their own PetaLinux 2024.1 installation; neither the
installer nor a license is included. `Dockerfile.petalinux` provides an
Ubuntu 22.04 base with PetaLinux host prerequisites, not the PetaLinux tools.
The wrapper mounts the repository at `/workspace`, and mounts the PetaLinux
installation read-only **at its original absolute host path**. PetaLinux setup
scripts contain absolute paths, so mounting it elsewhere does not work. A
writable cached copy of the installation's `.statistics` metadata is overlaid
at its original location. Project build data, extracted Yocto components,
temporary files, and container home data are bind-mounted from
`.cache/petalinux-2024.1-ubuntu22/`; native and container build state are kept
separate. Directories in `SCAM_APPS` are mounted read-only at their host paths.
Docker is a project convenience, not an AMD certification of Docker as a
supported PetaLinux host.

Native PetaLinux 2024.1 does not build on hosts with a very new GCC (Yocto
host recipes such as `m4` fail with GCC 15); use the container there.

### Why the base XSA

PetaLinux is configured from the base XSA, not from the applications. The XSA
lives at `hw/base/system.xsa` and nowhere else: `petalinux-config` empties
`petalinux/project-spec/hw-description/` before importing, so an XSA stored
there deletes itself.

### Config templates

`petalinux/project-spec/configs/config.template` and
`rootfs_config.template` are provided as starting points.
`make petalinux-config` copies them to `config` and `rootfs_config` if those
do not exist, and then runs `petalinux-config --get-hw-description`. From that
point on, the actual `config` and `rootfs_config` files are the source of
truth. After editing a template, run `make clean-petalinux-config` and then
`make petalinux-config`.

If you want to tweak the kernel or rootfs later:

    cd petalinux
    petalinux-config              # menuconfig
    petalinux-config -c rootfs
    petalinux-build

### Login

`rootfs_config.template` adds the user `petalinux` with password `petalinux`
and `sudo` rights; root has no password. `make deploy` and
`sw/host/collect_data.py` use this account. To change it, edit
`CONFIG_ADD_EXTRA_USERS` in the template, then
`make clean-petalinux-config petalinux`.

### What a release contains

| File | Use |
| :-- | :-- |
| `scam-zcu102-<version>.wic.xz` | Whole SD card image; write with `dd` or balenaEtcher |
| `scam-zcu102-<version>-boot.tar.gz` | `BOOT.BIN`, `image.ub`, `boot.scr`, `rootfs.tar.gz`, bitstreams; unpack into `out/` and run `make flash` |
| `scam-zcu102-<version>-sdk.sh` | Cross toolchain and sysroot for applications |
| `SHA256SUMS` | Checksums |

## Clean targets

| Target | Removes | Keeps |
|--------|---------|-------|
| `clean` | `clean-hw` + `clean-staged` | All sources, recipes, PetaLinux config and images |
| `clean-hw` | `hw/base/build`, `hw/base/system.xsa`, `build/apps`, `./out` | All sources, recipes, PetaLinux config |
| `clean-staged` | C/H files and `.bit.bin` copies staged into recipes | Recipes, all sources |
| `clean-petalinux-config` | config, config.old, rootfs_config, rootfs_config.old, plnx_syshw_data, flash_parts.txt, gen-machineconf.log*, .Xil/, busybox/, configs/, init-ifupdown/, rootfsconfigs/, systemd-conf/, .statistics, psu_init* | config.template, rootfs_config.template |
| `clean-petalinux-build` | `petalinux/images`, `petalinux/build`, `petalinux/.petalinux`, `/tmp/scam-petalinux-tmp` | Config, sources, container cache |
| `clean-container-state` | The whole container `components/` and `build/` cache, plus `tmp/` and `home/` | `build/downloads` and `build/sstate-cache` only |
| `clean-container-image` | Docker image scam-petalinux:2024.1-ubuntu22 | Everything else |
| `clean-downloads-cache` | `build/downloads`, `build/sstate-cache`, `components/yocto/downloads` | Everything else |
| `clean-build` | All of the above except the image and downloads caches, plus `build/` | downloads, sstate, sources, templates |

`clean-hw` removes the base template project, including any edits made to it
in the Vivado GUI.

### Container cache layout

The container keeps its PetaLinux state under `.cache/petalinux-2024.1-ubuntu22/`:

| Path | What it is |
|------|------------|
| `components/yocto/layers`, `sysroots`, `cache`, `conf`, `workspace` | The generated PetaLinux eSDK |
| `components/yocto/environment-setup-*`, `site-config-*`, `version-*` | Markers telling PetaLinux the eSDK is already set up |
| `build/downloads` | `DL_DIR` — fetched source tarballs |
| `build/sstate-cache` | `SSTATE_DIR` — build task cache |
| `sdk-statistics` | Writable overlay for the read-only installation's `.statistics` |

`components/yocto/downloads` is **not** the download cache; it only holds
`uninative`. The real `DL_DIR` is `build/downloads`.

Because the `environment-setup-*` marker is what PetaLinux checks, deleting
only `layers/`, `sysroots/` or `cache/` from `components/yocto/` leaves the
marker behind and every later build fails at `oe-init-build-env` with an empty
`[ERROR]`. Always remove `components/` whole. `make clean-container-state` does
this, and the container wrapper refuses to start if it finds the marker without
`layers/poky/oe-init-build-env`.
