# Build Guide

## Prerequisites

- Vivado 2024.1, with ZCU102 board files installed
- PetaLinux 2024.1
- For native PetaLinux builds, an AMD-listed supported Linux host
- Docker for the optional Ubuntu 22.04 PetaLinux container
- For SD flashing: `parted`, `mkfs.vfat`, `mkfs.ext4`, `tar`

Vivado remains a host prerequisite for building the XSA and bitstreams. The
container handles PetaLinux only; it consumes the XSA generated by Vivado.

## Verified hardware targets

The following targets completed successfully in the previous host build
session, including after `make clean-build`:

    make clean-build
    make base-xsa
    make tdc-bitstream
    make ct-bitstream

These results verify the current Vivado project scripts. They do not verify a
PetaLinux image build.

## Order of operations

    make base-xsa
    make tdc-bitstream
    make ct-bitstream
    make petalinux-config      # once
    make petalinux
    make sdcard

The same PetaLinux targets can run in the Ubuntu 22.04 container:

    PETALINUX_ROOT="$HOME/petalinux/2024.1" PETALINUX_ENV=container make petalinux-config
    PETALINUX_ROOT="$HOME/petalinux/2024.1" PETALINUX_ENV=container make petalinux

Each user supplies their own PetaLinux 2024.1 installation; neither the
installer nor a license is included. `Dockerfile.petalinux` provides an
Ubuntu 22.04 base with PetaLinux host prerequisites, not the PetaLinux tools.
The wrapper mounts the repository at `/workspace`, and mounts the SDK
read-only **at its original absolute host path**. PetaLinux setup scripts
contain absolute paths, so mounting the SDK elsewhere does not work. A
writable cached copy of the SDK's `.statistics` metadata is overlaid at its
original location. Project build data, extracted Yocto components, temporary
files, and container home data are bind-mounted from
`.cache/petalinux-2024.1-ubuntu22/`; native and container build state are kept
separate. Docker is a project convenience, not an AMD certification of Docker
as a supported PetaLinux host.

## Why base-xsa first

PetaLinux is configured from the base XSA, not the application XSAs.
`make base-xsa` writes `system.xsa` directly into
`petalinux/project-spec/hw-description/`. `make petalinux-config` then
reads it.

`make clean-build` removes generated Vivado products, host PetaLinux state,
container PetaLinux state, download/shared-state caches, and temporary work
directories. It preserves the project sources and configuration.
Build the base XSA and bitstreams again with `make base-xsa`,
`make tdc-bitstream`, and `make ct-bitstream`.

## Config templates

`petalinux/project-spec/configs/config.template` and
`rootfs_config.template` are provided as starting points.
`make petalinux-config` copies them to `config` and `rootfs_config`
and then runs `petalinux-config --get-hw-description`. From that point
on, the actual `config` and `rootfs_config` files are the source of
truth.

If you want to tweak the kernel or rootfs later:

    cd petalinux
    petalinux-config              # menuconfig
    petalinux-config -c rootfs
    petalinux-build

## Adding a new C application

1. Copy `sw/tdc/` as a template.
2. Adjust the register map and readout logic.
3. Add a `.bb` recipe under
   `petalinux/project-spec/meta-user/recipes-apps/`.
4. `make petalinux` -- the new binary appears in `/usr/bin/`.

## Adding a new bitstream

1. Create a new Vivado project under `hw/<name>/`, layering on the base.
2. `make bitstreams` will only build TDC and CT unless you add a target.
3. Drop the resulting `.bit.bin` into
   `petalinux/project-spec/meta-user/recipes-bsp/fpga-bitstreams/files/`.
4. Edit `fpga-bitstreams.bb` to install the new file.
5. `make petalinux` -- the new bitstream is now in `/lib/firmware/`.
